## 1. 이 프로젝트가 무엇인가

**AI와 함께 실제 구조의 짜임·접합·결구를 연구하고, 레이저/CNC로 직접 깎아 검증하는 작업.**
효율이 목적이 아니라 결구 자체(무엇이 잠그는가, 어떻게 드러나는가)를 연구하는 것이 목적이다.

- 처음에는 한옥 결구(장부, 주먹장, 메뚜기장 등)로 시작했지만, 2026-11-17에 사용자가 **한옥에 한정하지 않기로** 했다. 가구, 현대 목구조, 금속을 섞은 접합까지 포함한다.
- 같은 날 **결구가 디자인으로 드러나는 방식**도 연구 대상에 넣었다 (아래 4절).
- 결과물은 실물로 깎아 끼워 보는 것까지가 작품이다.

## 2. 사용자 정보와 작업 규칙

- 이주형. 건축 전공 휴학 중, 설계사무소 인턴, AI 응용 복수전공. **답은 한국어로.**
- **Python을 쓰지 않는다.** 윈도우용 결과물은 내장 Python을 같이 묶어 `.bat` 더블클릭으로 돌아가야 한다.
- 라이노(Rhino)를 쓴다 → 3D 결과는 `.3dm`.
- 화면·그림 스타일: 무채색 + 블루 계열만, 흰 배경, 검정 버튼, 글꼴 Pretendard (코드에 내장되어 있음).
- zip은 Python `zipfile`로 만든다 (윈도우 탐색기에서 한글 이름이 깨지지 않게). 파일 이름에 버전과 날짜를 붙인다.
- 그래스호퍼 알고리즘 생성은 **별도 스레드/주제**로 분리되어 있다. 이 프로젝트에서 이을 때는 결과를 GhPython으로 내보내는 정도로 연결한다.

## 3. 연구 질문

1. **결구는 무엇으로 잠기는가.** 끼우는 방향 하나만 남기고 나머지를 막는 원리를 검사기로 수치화한다.
2. **결구는 어떤 요소의 조합인가.** 장부·주먹장·턱(걸침)·없음을 높이 방향 층별 요소로 쪼갠 "결구 문법".
3. **그 문법이 처음 보는 조건에서도 통하는가.** 다른 각도·단면·부재 수에서 생성기가 잠기는 결구를 만들고, 각 후보가 어느 요소를 물려받았는지 계보로 보여 준다.
4. **결구는 디자인으로 어떻게 드러나는가.** 같은 구조 조건에서 표현 목표만 바꾸면 어떤 결구가 나오는가.
5. **실물로 맞는가.** 레이저 적층으로 깎아 끼워 보고 헐거움·뻑뻑함·쪼개짐을 기록해 공차와 검사 기준을 고친다.

## 5. 지금까지 만든 것과 결과

### M1 — 전통 결구 라이브러리 + 검사기 (2026-11-09)
- 전통 결구 9종을 복셀 격자(1칸 5mm, 단면 120×150mm)로 옮김: 장부, 턱장부, 주먹장, 반턱(십자), 반턱주먹장, 주먹장이음, 메뚜기장이음, 반턱이음, 안장맞춤(기둥-보).
- 검사기가 "어느 방향으로 빠지는가"를 스스로 판정. 결과가 전통 상식과 맞음: 7종은 한 방향만(좋음), 주먹장이음은 위아래 미끄러짐(보통), 반턱이음은 네 방향(약함).
- 결과: `m1_전통결구_v0.1/` (확인 그림, 결구별 그림, 조립·분해 3dm, 검사결과.json)

### M2 — 두 부재 결구 생성기 (2026-11-16)
- 결구 문법: 부재 높이를 층으로 나누고, 층마다 장부·주먹장·턱/걸침·없음 중 하나 + 비율. 진화 탐색(세대 26, 개체 48)으로 새 조합을 찾음.
- 임의 사잇각 지원 (90°, 60°, 45° 시험).
- 점수: 한 방향만 빠짐, 당김 저항(주먹장류), 아래로 빠지지 않음, 한 덩어리, 얇은 살, 결 방향 짧은 살, A 단면 잔존, 얇은 층 감점, 주먹장 벌어짐(10mm 미만 감점), 전통과 다른 꼴이면 가산.
- 결과: `m2_생성후보_v0.2/` (조건별 후보 5개 + 전통 기준 비교 그림, 층별 평면, 층별 솔리드 3dm)
- **발견 1 — 숨은 주먹장**: 60°·90°에서 "위층은 넓게 묻는 걸침, 아래층에 작은 주먹장" 조합이 거듭 나옴. 위에서 보면 단순한 턱인데 속에서 잠긴다. 전통 주먹장보다 A 윗면이 덜 따인다.
- **발견 2 — 빗각의 약점**: 주먹장 옆면을 B 부재 축에 맞춰 깎으니 60°·45°에서 A 쪽 귀퉁이가 뾰족하게 남음 (쪼개지기 쉬움). 아직 안 고침.

### 세 부재 모서리 — 다리 + 장선 2 (2026-11-17)
- 사용자가 다음 실험으로 고른 노드. 사진 02 꼴.
- 문법: 층마다 장선 X·Y가 다리 속으로 무엇을 넣는지 + 다리 속에서 겹칠 때 누가 이기는지(우선순위, 층마다 바꾸면 장선끼리 엇물림) + 다리가 장선 위로 솟는 높이 + 장선을 가운데/바깥면에 맞춤.
- 조립 순서 찾기: 다 조립된 상태에서 부재를 하나씩 빼는 순서를 찾고, 처음에 빠지는 부재를 **열쇠 부재**(마지막에 끼워 전체를 잠그는 부재)로 표시.
- 표현 목표: 노드 윗면 + 바깥 옆면에서 보이는 부재 경계 길이(다리 한 변으로 나눔. 맞댐만 하면 약 10). **드러냄**은 많을수록, **숨김**은 적을수록 가산.
- 결과: `node3_세부재모서리_v0.1/` (드러냄 3개, 숨김 3개, 기존 꼴 3개 그림 + 3dm 9개 노드 + 후보목록.json)
- **발견 3 — 드러냄이 더 단단하다**: 드러냄 후보(한 장선이 다리를 관통해 바깥에 끝면이 보이고, 다른 장선이 다리 머리에 걸침)가 구조 점수 112~116. 기존 꼴인 장부 모서리 74, 사개(반턱) 모서리 101, 솟은 매듭 74보다 높음.
- **발견 4 — 숨기면 잠금을 잃는다**: 숨김 후보(다리 속 장부만)는 바깥이 깨끗하지만 열쇠 장선이 자기 축으로 빠질 수 있어 핀·접착이 필요 (구조 약 100). 실물로 검증할 연구 주장.

실행 환경: Python 3 + `numpy scipy matplotlib rhino3dm shapely mapbox_earcut` (`ezdxf`는 M3 DXF용으로 설치만 됨).
시간: run_m1 약 15초, run_m2 약 4분, run_node3 약 2분.
`M2_CACHE=후보목록.json`, `N3_CACHE=후보목록.json` 환경변수를 주면 탐색 없이 그림만 다시 그린다.

### 설계상 결정 (왜 이렇게 했나)
- **검사는 복셀, 형상은 다각형.** 빠짐·덩어리·얇은 살 검사는 복셀이 쉽고 확실하다. 그림·라이노·재단은 빗면이 계단지지 않도록 같은 정의에서 다각형으로 만든다.
- **레이저 적층과 층 문법이 같은 구조.** 층별 평면 = 그대로 자를 판 모양이다.
- **비스듬한 방향 빠짐 검사**는 복셀 계단끼리 가짜로 걸리지 않도록 고정 부재를 한 칸 깎고(erosion) 표면 칸만 추적한다. 실물에서는 빗선이 곧게 잘리므로 계단이 없다.
- **matplotlib 3D를 쓰지 않는다.** 면 앞뒤 순서를 자주 틀려서 자체 렌더러(raster.py)를 만들었다.
- 큰 데이터셋으로 신경망을 학습하는 방식은 쓰지 않는다 (결구 3D 데이터가 적음). 손으로 옮긴 전통·기존 결구 → 요소 문법 → 진화 탐색 + 검사기.

## 7. 한계와 알려진 문제

- 점수 가중치는 가정이다. 강도는 구조 해석(FEM)이 아니라 맞물림·남은 단면 같은 대리 지표다.
- 빗각 주먹장의 뾰족한 귀퉁이 (발견 2) — 옆면을 A 면에 수직으로 두는 옵션이 필요.
- 세 부재 모서리는 직교(90°)만, 장선 높이는 같다고 가정. 다리 솟음은 0/30/60mm만.
- 표현 목표는 "보이는 경계 길이" 하나뿐. 재료 대비·틈·내민 길이는 아직 점수에 없음.
- 쐐기·키 같은 세 번째 부재(잠금장치의 사물화)는 아직 문법에 없음.
- 실제 판 두께·레이저 작업대 크기를 아직 받지 못했다. 정해지지 않으면 **3mm MDF, 600×400mm**로 가정하기로 사용자에게 말해 둠.
- 실물 시험은 아직 한 번도 안 했다.
